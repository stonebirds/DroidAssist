# DroidAssist 普通用户快速开始

本文只面向直接使用软件的用户，不要求任何开发知识。

## 需要准备

- 两台 Android 8.0 或更高版本的手机。
- 一台可以联网的 Mac 或 64 位 Windows 电脑。
- 从 [GitHub Releases](https://github.com/stonebirds/DroidAssist/releases/latest) 下载的 Android APK 和对应电脑服务包。

## 第一步：安装手机应用

在两台手机上安装 `DroidAssist-1.1.6-release.apk`。

如果手机上安装过开发测试阶段的 `1.0.8` 调试版，请先卸载旧版再安装正式版。调试版与正式版的签名不同，Android 不允许直接覆盖安装；卸载会清除旧版保存的服务器地址、匹配码和授权数据。

如果 Android 提示“不允许安装未知应用”，进入提示中的系统设置，只允许当前浏览器或文件管理器完成这一次安装。安装完成后可以关闭该权限。

## 第二步：启动电脑服务

### Mac

1. Apple 芯片 Mac 下载 `macOS-arm64`，Intel Mac 下载 `macOS-x64`。
2. 双击 ZIP 完整解压。
3. 进入解压后的目录，双击 `1-Start-DroidAssist.command`。
4. 如果 macOS 阻止运行，在“系统设置 -> 隐私与安全性”中选择“仍要打开”，然后再次双击。

### Windows

1. 下载 `Windows-x64` 服务包并完整解压。
2. 进入解压后的目录，双击 `1-Start-DroidAssist.cmd`。
3. 如果 Windows 显示安全提醒，确认文件来自 DroidAssist GitHub Release 后选择继续运行。

启动脚本会自动完成以下工作：

- 启动本地 Ktor 服务。
- 创建 SQLite 数据库。
- 启动 Cloudflare Quick Tunnel。
- 复制服务器地址到电脑剪贴板。
- 打开包含服务器地址、二维码和状态的浏览器页面。

不要从 ZIP 预览窗口直接运行，必须先完整解压。

## 第三步：注册两台手机

两台手机分别执行：

1. 打开 DroidAssist。
2. 进入底部“设置”。
3. 点击“服务器地址”右侧的扫码图标，扫描电脑页面上的二维码；扫码页也可以打开手电筒或从相册选择图片。相册中有多个二维码时，选择要使用的服务器地址即可。也可以复制并手动粘贴完整的 `https://...trycloudflare.com` 地址。
4. 点击“注册本机”。
5. 确认页面显示“设备注册：已注册”。

两台手机必须填写完全相同的地址。Quick Tunnel 地址变化后，两台手机都要更新并点击“重新连接服务”。

## 第四步：准备被协助手机

1. 打开“本机”页面。
2. 点击“开启无障碍控制”。
3. 在系统无障碍设置中启用 DroidAssist，然后返回应用。
4. 点击“临时授权”或“永久授权”。
5. 点击“复制完整授权信息”，通过聊天工具发送给协助端。

## 第五步：发起协助

1. 协助端打开“设备”页面。
2. 复制被协助端发来的完整授权信息，点击“从剪贴板填入授权”；也可以手动输入匹配码和连接密码。
3. 点击“发起连接”。
4. 被协助端在弹窗中点击“允许”。
5. Android 弹出录屏提示后，选择共享整个屏幕并允许。
6. 画面连接成功后，协助端会自动进入远程屏幕。

底部控制面板可以执行返回、主页、最近任务、退出远控页面和结束协助。控制面板采用固定高度，选项较多时在面板内部上下滚动；点击“收起控制”或面板外的画面即可关闭。退出远控页面不会断开连接；面板收起后，点击悬浮按钮可以再次打开。需要彻底断开时点击“结束并断开协助”，或回到“设备”页点击“断开”。

画质默认使用“自适应”，WebRTC 会根据网络带宽平衡清晰度和流畅度。也可以切换为“手动”，选择 720p/1080p 和 10/15/20/30 fps。1080p/30 fps 更清晰但需要更好的网络；画面卡顿时优先改为 720p/15 或 20 fps。

## 停止服务

结束手机共享：协助端点击“结束并断开协助”或“断开”；也可以在被协助手机“本机”页面点击“停止共享”。

停止电脑服务：

- Mac：双击 `3-Stop-DroidAssist.command`。
- Windows：双击 `3-Stop-DroidAssist.cmd`。

数据库不会被停止脚本删除。下次启动仍会保留设备和授权信息。

## 常见问题

### 电脑页面没有自动打开

双击 `2-Status` 开头的文件。仍未打开时，查看软件数据目录中的日志：

- Mac：`~/Library/Application Support/DroidAssist/runtime`
- Windows：`%LOCALAPPDATA%\DroidAssist\runtime`

### 提示 Cloudflare HTTP 429

这是 Cloudflare 匿名 Quick Tunnel 的临时限流，不是 DroidAssist 本地服务或安装包损坏。新版启动脚本会自动尝试三次；仍失败时不要连续反复启动，请等待 10-20 分钟后重试，或切换电脑网络后再启动。

### 二维码区域空白

`1.1.1` 起二维码完全在本机离线生成，不依赖第三方二维码网站。请确认服务包已经完整解压，且 `web` 目录中的文件没有被安全软件隔离；也可以先使用“复制地址”。

### 手机显示已注册但收不到请求

确认两台手机的服务器地址完全一致，并分别点击一次“重新连接服务”。

### 有画面但不能操作

`1.1.4` 起，应用不仅检查系统开关，还会确认 DroidAssist 无障碍服务已经实际连接；`1.1.5` 还会在服务连接状态变化时立即刷新权限显示。服务未就绪时，被协助端不能允许连接，控制失败原因也会显示在协助端。

如果小米、荣耀等系统仍提示无障碍服务未连接，请在被协助手机的系统设置中关闭再重新开启 DroidAssist 无障碍服务，并允许应用后台运行。然后重新发起协助。双方都可以在“设置”页打开诊断日志并复制给维护人员。

### 打开相机后远端画面变黑

DroidAssist `1.1.2` 起内置扫码页使用 TextureView，正常情况下可以继续被整屏共享。部分第三方相机、支付、密码、锁屏页面会使用 Android 保护画面，系统会在 MediaProjection 中主动显示黑色；DroidAssist 无法绕过该安全限制。退出受保护页面后，远端画面应自动恢复，不需要重新连接。

### 允许后一直没有画面

当前版本没有 TURN。在部分企业网络、校园网、严格 NAT 或受限移动网络中，WebRTC P2P 可能无法连接。这个问题与录屏、通知和无障碍权限无关。可先让其中一台手机切换 Wi-Fi/移动网络重试；需要稳定跨网络使用时，必须部署 TURN。

`1.1.5` 只有在 ICE 已连接且收到远程视频轨道后才会打开远控页，并会分别显示画面首帧和控制通道状态。ICE 失败时不会再进入假连接黑屏页，日志还会记录候选类型 `host`、`srflx` 或 `relay`，但不会记录 IP 地址。

如果仍然没有画面，请在两台手机的“设置”页分别点击右上角日志按钮，点击复制，将两份日志一起提供给维护者。日志会区分系统录屏、WebSocket 信令、offer/answer、ICE、DataChannel 和首帧渲染阶段，不包含连接密码、设备令牌、SDP 或 ICE 地址。
