# DroidAssist 实现说明

## 1. 实现范围

本轮实现目标是完成一条可在两台 Android 设备上实际验证的远程协助链路：注册设备、建立授权、实时通知连接请求、由被协助端确认、系统授权整屏录制、P2P 传输画面、执行远程手势和系统导航，并在任一端结束后正确清理会话。

当前结果是功能原型，已经覆盖核心链路，但不等同于可直接公开运营的远控产品。生产化缺口列在文末。

## 2. 实现阶段

### 阶段一：工程与协议骨架

- 将 Android 工程配置为 API 26 最低版本、API 36 目标版本。
- 建立 `app`、`protocol`、`server` 三模块 Gradle 工程。
- 在 `protocol` 中统一 REST 和 WebSocket 序列化模型。
- 建立 Ktor CIO 服务和 SQLite 持久层。

模块拆分的核心考虑是让 Android 和服务端编译期共享协议类型，同时避免服务端依赖 Android 代码。

### 阶段二：设备身份与授权

- 首次运行生成 installation ID，并在 Android Keystore 创建 EC 密钥对。
- 服务端为安装实例分配设备 ID、9 位匹配码和设备令牌。
- 设备令牌及授权密码只保存哈希。
- 实现临时授权、永久授权、错误次数限制、可信设备和撤销授权。
- 使用 DataStore 保存服务器地址、注册信息及最近 5 个匹配码。

临时授权用于一次性协助；永久授权用于建立长期设备关系。无论授权类型如何，当前实现都保留被协助端的连接确认和 Android 系统录屏确认。

### 阶段三：从轮询改为长连接

- 为每台已注册设备建立 `/signal/{deviceId}` WebSocket。
- 服务端维护设备到 socket 的内存映射，并实时更新在线状态。
- 新会话创建后立即推送 `session_request`。
- Android 端断线后每 2 秒重连，重连时服务端补发仍有效的待确认请求。
- offer、answer、ICE 和 hangup 复用同一信令连接。

这一步消除了连接请求的业务轮询。REST 仍用于有明确请求/响应语义的注册、授权、建会话和管理操作。

### 阶段四：屏幕采集生命周期

- 被协助端允许连接后，应用自动发起 MediaProjection 系统授权。
- Android 13 及以上先处理通知权限，再启动前台共享服务。
- Android 14 及以上显式请求默认显示屏的整屏捕获，避免应用窗口级共享导致切换应用后画面不更新。
- `ScreenShareService` 持有前台通知，并把系统授权结果传给 `WebRtcManager`。
- 停止服务时结束采集并通知对端挂断。

应用不能代替用户确认系统录屏权限。“连接后默认开始协助”在实现上的含义是：不再提供额外的应用内“开始屏幕协助”按钮，连接获准后直接进入 Android 系统授权流程。

### 阶段五：WebRTC 实时画面

- 使用 `io.github.webrtc-sdk:android` 初始化 PeerConnectionFactory。
- 被协助端创建屏幕视频轨道和 offer，协助端创建 answer。
- 使用公共 Google STUN 发现候选地址。
- 协助端收到远程 VideoTrack 后绑定 `SurfaceViewRenderer`。
- 根据远端实际尺寸更新宽高比，避免画面被错误拉伸。
- 收到远程视频后自动打开独立的全屏查看页面。

早期联调中出现过 ICE candidate 先于远端 SDP 到达的问题。现在会先缓存 candidate，等 `setRemoteDescription` 成功后统一应用，避免偶现连接失败。

### 阶段六：远程控制

- 在 WebRTC PeerConnection 上建立 `control` DataChannel。
- 协助端把触摸坐标归一化，发送点击、长按和滑动命令。
- 被协助端 AccessibilityService 将坐标映射到实际屏幕，并使用 `dispatchGesture` 执行。
- 返回、Home 和最近任务使用无障碍全局动作。
- 控制命令只在 DataChannel 状态为 `OPEN` 时发送。

远程控制依赖被协助端手动开启无障碍服务。该权限不能由应用静默授予，也不能突破 Android 锁屏、系统授权框和安全页面限制。

### 阶段七：交互与会话清理

- 主界面调整为“设备 / 本机 / 设置”三个页面。
- “设备”页负责发起连接、复用最近匹配码、查看在线和可信设备。
- “本机”页负责展示匹配码、创建授权、查看共享及无障碍状态。
- “设置”页负责服务器地址、注册状态和诊断信息。
- 独立远控页首次展开底部面板，收起后通过悬浮按钮恢复。
- 底部面板集中放置返回、Home、最近任务、收起和退出操作，最大化远程画面空间。
- 全局控制改为固定尺寸图标按钮和单行标签，避免窄屏按钮文字换行。
- 控制端通过同一 DataChannel 下发画质参数，被控端无需重新建立会话即可切换捕获尺寸和帧率。
- 默认自适应模式以 1080p/30 fps 为上限，使用 WebRTC 带宽估计和 `BALANCED` 降级策略；手动模式支持 720p/1080p 与 10/15/20/30 fps。
- 本机弹窗在用户点击允许或拒绝后立即离开交互状态，防止异步请求期间多次点击。
- 共享停止时发送 `hangup`；对端收到后退出冻结画面并释放 WebRTC 资源。

### 阶段八：低门槛配置与便携部署

- Mac 和 Windows 启动脚本识别 Cloudflare Quick Tunnel `429` 限流，最多自动尝试三次并分段等待。
- 便携包内置经过 SHA-256 校验的二维码生成脚本，启动页不再依赖外部二维码网站。
- Android 设置页使用相机扫描服务器二维码，并只接受带有效主机的 HTTP/HTTPS 地址。
- 扫码页固定竖屏，提供关闭、手电筒和相册二维码识别；相册大图先按比例缩放再在后台解码。
- 内置扫码相机使用 TextureView，避免普通相机 Surface 在 MediaProjection 中显示黑屏。
- 被协助端可复制包含服务器地址、匹配码和连接密码的完整授权文本。
- 协助端只在用户主动点击后读取剪贴板，并解析填入匹配码和连接密码；授权密码不会写入历史记录。
- 设置页右上角提供持久化诊断日志，记录请求、录屏、信令、ICE 和首帧状态，并过滤敏感连接内容。
- 服务端为短暂离线的设备暂存最多 256 条信令，重连后按顺序补发，避免 offer/answer/ICE 被直接丢弃。
- PeerConnection 使用多个 STUN 入口；ICE 失败后由被协助端最多自动发起两次 ICE restart。

## 3. 关键技术决策

### 信令与媒体分离

Ktor 只处理低带宽的身份、授权、会话和信令数据。屏幕视频及实时控制使用 WebRTC P2P，降低服务端带宽压力，也避免服务端接触屏幕内容。

### 单 APK 双角色

同一 Android 应用既可以发起协助，也可以接受协助。角色由当前 WebRTC 会话决定，减少测试、安装和协议兼容成本。

### 明确的用户授权链

实现保留三层边界：连接密码、被协助端应用内确认、Android MediaProjection 系统确认。无障碍权限还需用户在系统设置中单独开启。

### 本地保存便利信息

最近匹配码只保存在发起连接的手机 DataStore 中，减少重复输入。连接密码不进入最近记录。设备私钥留在 Android Keystore，服务端保存公钥和令牌哈希。

### 会话资源集中管理

WebRTC 的 SDP、ICE、视频源、渲染轨道、DataChannel 和停止流程集中在 `WebRtcManager`，避免 Activity 或 Compose 重组直接持有底层资源。

## 4. 已处理的问题

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 两台手机都显示注册但收不到连接请求 | 仅靠请求接口无法实时通知 | 增加按设备认证的 WebSocket 长连接和断线重连 |
| 允许整屏共享后没有继续 | 应用内状态与系统授权流程未串联 | 会话确认成功后发出捕获请求，由 Activity 启动 MediaProjection |
| 切换被协助端应用后画面不变化 | 捕获范围可能落在单应用窗口 | Android 14+ 使用默认显示屏整屏捕获配置 |
| 远程画面出现后协助端崩溃 | 网络状态读取缺少权限 | Manifest 增加 `ACCESS_NETWORK_STATE` |
| 连接偶发无法出画面 | ICE candidate 早于 SDP 到达 | SDP 就绪前缓存远端 ICE candidate |
| 允许弹窗需要多次点击 | 网络确认期间弹窗仍保持可交互 | 首次响应立即清除待处理弹窗，失败时恢复 |
| 停止共享后协助端停在最后一帧 | 缺少对端结束通知 | 发送 `hangup` 并在两端统一释放资源 |
| 匹配码每次重复输入 | 没有本地历史 | DataStore 保存最近 5 个匹配码 |
| 远程画面占用空间小 | 画面嵌在主页面 | 新增独立远控页和可收起的底部操作面板 |
| 电脑二维码加载失败 | 页面依赖外部二维码接口 | 将二维码生成器打入便携包并在浏览器本地生成 |
| 服务启动遇到 HTTP 429 | Cloudflare 限制匿名 Quick Tunnel 申请 | 自动分段重试，并提示等待或切换网络 |
| 地址、匹配码和密码输入繁琐 | 信息分散且依赖手工输入 | 增加扫码地址及完整授权文本的复制和解析 |
| 授权后偶发一直没有画面 | WebSocket 重连窗口内信令会被丢弃，单 STUN 失败后不恢复 | 暂存并补发信令，增加多 STUN 和 ICE restart |
| 用户无法提供有效故障信息 | 关键状态只存在系统 Logcat | 增加应用内持久化诊断日志及一键复制 |
| 远端画面模糊 | 捕获长边固定为 1280，窄长屏实际只有约 606p 短边 | 改为短边 720p/1080p 档位，并增加默认网络自适应和手动帧率 |
| 远控按钮文字换行 | 三个横向按钮同时容纳图标和文字 | 使用固定图标按钮及下方单行中文标签 |
| 打开内置扫码后远端黑屏 | ZXing 默认 SurfaceView 不进入 MediaProjection 合成画面 | 内置扫码改用 TextureView；第三方安全 Surface 仍遵循 Android 遮黑策略 |

## 5. 构建与验证过程

### 自动检查

当前完整检查命令：

```bash
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

该命令覆盖 Android 单元测试、Lint 和调试 APK 构建。服务端与共享协议会作为依赖参与编译。

### 双端验证

使用 Pixel 7 和 Pixel 9 模拟器完成以下流程：

1. 两端注册并保持 WebSocket 在线。
2. 协助端通过匹配码和密码创建会话。
3. 被协助端只需点击一次允许，随后自动出现系统整屏共享确认。
4. 双端 ICE 进入 `CONNECTED`，DataChannel 进入 `OPEN`。
5. 协助端显示实时远程画面。
6. 点击、底部面板和 Home 动作生效。
7. 被协助端停止共享后，协助端收到挂断并退出远控页面。

已验证调试包：

```text
releases/DroidAssist-1.0.8-debug.apk
SHA-256 3aba37d16151db03384ae3eb479d3d539a6f769427c80f5bc343676047037e7f
```

APK 是本机构建产物，不纳入 Git；通过源码可执行相同构建。

## 7. 已知限制与后续建议

### 网络可靠性

当前只使用 STUN。在蜂窝网、对称 NAT、企业防火墙或 UDP 受限网络中，P2P 可能失败。下一步应部署 coturn，并为 PeerConnection 配置带认证的 TURN URL。

### 服务端可靠性

WebSocket 连接表存于单进程内存，不能直接横向扩展。生产环境需要固定域名、TLS、进程守护、数据库迁移、共享在线状态、速率限制、结构化日志、监控和备份策略。

### 身份与授权

当前已生成设备 EC 密钥，但业务请求尚未使用私钥签名。生产版本应加入挑战签名、令牌轮换、设备所有权账户、授权审计和服务端强制会话关闭。

### Android 兼容性

应在不同厂商、Android 8 到 Android 16、横竖屏、多窗口、锁屏、弱网和后台限制场景做真机矩阵测试。需要特别验证 MediaProjection 前台服务、通知权限和无障碍手势在各厂商 ROM 上的行为。

### 体验与质量

后续可以增加远端分辨率和码率自适应、连接质量提示、旋转处理、剪贴板、文本输入、文件传输、会话计时、重连恢复、崩溃收集及 Compose UI 自动化测试。
